# Онлайн-кінотеатр

Навчальний проєкт на Python: консольний застосунок, що імітує роботу невеликого
онлайн-кінотеатру. Робота з базою даних — через **SQLAlchemy ORM** (декларативний
стиль 2.0), СУБД — **PostgreSQL**.

- `models.py` — моделі та зв'язки між ними
- `database.py` — рядок підключення, `engine`, фабрика сесій
- `services.py` — CRUD-операції та бізнес-логіка
- `queries.py` — аналітичні запити (агрегація, підрахунки, рекомендації)
- `seed.py` — наповнення бази демонстраційними даними
- `main.py` — консольне меню та точка входу
- `sql_task.py` — текст навчального завдання

## Запуск

```bash
pip install sqlalchemy psycopg2-binary
python main.py
```

Перед першим запуском треба створити базу `online_cinema` у PostgreSQL і вказати
власні параметри підключення в `database.py`. Таблиці створюються автоматично —
`Base.metadata.create_all()` викликається на старті.

Щоб наповнити базу демонстраційними даними, розкоментуй виклик `seed_database()`
у `main()` і запусти застосунок один раз.

## Структура бази даних

Вісім основних таблиць і дві зв'язувальні:

| Таблиця | Призначення |
|---|---|
| `users` | користувачі (`username`, `email` — обидва унікальні) |
| `movies` | фільми (назва, опис, рік, тривалість) |
| `genres` | жанри (унікальна назва) |
| `actors` | актори (ім'я, рік народження) |
| `ratings` | оцінки фільмів користувачами |
| `favorites` | обране |
| `subscriptions` | підписки (план, початок, закінчення) |
| `watch_history` | історія переглядів |
| `movie_genres` | зв'язок фільм ↔ жанр (many-to-many) |
| `movie_actors` | зв'язок фільм ↔ актор (many-to-many) |

Зв'язки «один-до-багатьох» (`User → Rating`, `Movie → WatchHistory` тощо) оголошені
з `cascade="all, delete-orphan"`: видалення фільму прибирає його оцінки, обране та
записи в історії, не залишаючи «висячих» рядків.

`Rating` і `Favorite` захищені `UniqueConstraint` по парі `(user_id, movie_id)` —
один користувач не може двічі оцінити чи двічі додати в обране той самий фільм.
Це обмеження на рівні бази, а не лише перевірка в коді: навіть якщо логіка
застосунку помилиться, база не пропустить дубль.

Зв'язки «багато-до-багатьох» реалізовані через `secondary`-таблиці без окремих
моделей — у `movie_genres` і `movie_actors` немає власних атрибутів, лише два
зовнішні ключі, тому повноцінний ORM-клас для них зайвий.

## Розділення відповідальності

Код розкладений по шарах, і це не формальність:

**`services.py`** — усе, що змінює стан бази: створення, оновлення, видалення,
додавання оцінок і підписок. Функції приймають `session` першим аргументом і не
створюють її самі — сесією керує викликач (`main.py` відкриває одну на весь
життєвий цикл через контекстний менеджер).

**`queries.py`** — усе, що тільки читає: пошук за назвою, топ за переглядами,
топ за середнім рейтингом, статистика користувача, рекомендації. Тут живуть
агрегатні запити з `func.count()`, `func.avg()`, `group_by` та `order_by(desc(...))`.

**`main.py`** — лише введення/виведення. Жодного SQL, жодних запитів до бази
напряму: меню збирає дані від користувача, передає у відповідну функцію й друкує
результат. Функції `print_movie()`, `print_genres()`, `print_movie_details()`
відповідають тільки за форматування.

Такий поділ означає, що консольний інтерфейс можна замінити на веб чи API, не
торкаючись `services.py` і `queries.py`.

## Валідація та обробка помилок

`rate_movie()` перевіряє діапазон оцінки (1–10), існування користувача й фільму,
а також відсутність попередньої оцінки — і на кожну проблему підіймає `ValueError`
з конкретним повідомленням. `main.py` ловить його й показує текст користувачеві,
не роняючи застосунок.

Функції, де «не знайдено» — це нормальний сценарій, а не помилка (`delete_movie()`,
`add_to_favorites()`, `add_genre_to_movie()`), повертають `False` замість винятку.
Виняток піднімається там, де користувач зробив щось некоректне; `False` — там, де
дія просто не спрацювала.

## Підписки

`watch_movie()` перед записом у історію переглядів викликає
`is_subscription_active()`: без активної підписки перегляд не записується.
Перевірка робиться запитом до бази з порівнянням поточного часу з
`started_at` / `expires_at`, а не збереженим прапорцем — прапорець довелося б
оновлювати за розкладом, і він встиг би застаріти.

Для демонстрації строки навмисно короткі: `Standard` — 30 хвилин, `Premium` —
60 хвилин від моменту створення. Це дозволяє побачити, як застосунок поводиться
після закінчення підписки, не чекаючи місяць.

## Аналітика

- **Топ за переглядами** — `JOIN` з `watch_history`, `count()` по `movie_id`
- **Топ за рейтингом** — `JOIN` з `ratings`, `avg()` по значенню оцінки
- **Улюблений жанр користувача** — подвійний `JOIN` (історія → фільм → жанри)
  з підрахунком по жанру
- **Статистика користувача** — кількість переглядів, оцінок, обраного, середня
  оцінка, улюблені жанри й фільми, статус підписки
- **Рекомендації** — фільми, яких немає в історії переглядів користувача
  (підзапит із `not_in`)

Функція `get_favorite_by_user()` повертає **список**, а не один елемент: якщо два
жанри мають однакову кількість переглядів, обидва потраплять у відповідь. Брати
просто перший рядок було б довільним вибором між рівними варіантами.
